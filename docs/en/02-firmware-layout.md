# 02 — Firmware layout

The authoritative partition table is **shipped inside the firmware update**, in
`0300_partconf/partinf.conf` (generated by Sony on 2013-08-01). It matches what the
kernel sees as `/dev/nflashaN`.

## Partition table

| Device | Start | Size | Mount | Filesystem | Role |
|---|---|---|---|---|---|
| — | `0x00000000` | 256 KiB | — | — | bootloader |
| nflasha1 | `0x00040000` | 6 MiB | — | vfat | SYSTEM (Updater) |
| **nflasha2** | `0x00640000` | 13 MiB | **`/setting`** | vfat | **settings — `Backup.bin` lives here** |
| nflasha3 | `0x01340000` | 30 MiB | `/system` | raw | **AV pipeline (`av-cam.bin`)** |
| nflasha4 | `0x03140000` | 10 MiB | — | raw | MPR flash backup |
| nflasha5 | `0x03B40000` | 60 MiB | `/wbi` | wbi | Warm Boot Image |
| nflasha6 | `0x07740000` | 5 MiB | — | vfat | "Jiritsu" |
| nflasha7 | `0x07C40000` | 4 MiB | `/rootfs` | raw | root filesystem |
| nflasha10 | `0x08040000` | 5 MiB | `/tmp` | vfat | work area (**persistent flash, not tmpfs**) |
| nflasha11 | `0x08540000` | 6 MiB | `/log` | vfat | logs |
| nflasha15 | `0x08B40000` | 100 MiB | `/usr` | raw | **Linux userland (cramfs)** |
| nflasha16 | `0x0EF40000` | 82.75 MiB | `/android/system` | raw | Android system |
| **nflasha17** | `0x14200000` | 99.75 MiB | **`/android/data`** | vfat | **Android data — FAT16, installed APKs** |
| nflasha18 | `0x1A5C0000` | 20 MiB | `/lens` | vfat | lens data |
| nflasha23 | `0x1B9C0000` | 1 MiB | `/PMBP` | prfile | PMBP |

End of NAND: **`0x1BAC0000` = 463.75 MiB**.

Partitions with size 0: nflasha8, 9, 12, 13, 14, 19–22, 24–30.

## What an update actually rewrites

`0701_part_image_sum/part_image.sum` lists exactly **five** images:

| Image | bytes | CRC32 |
|---|---|---|
| `nflasha3` (`/system`) | 11 489 040 | `0c047870` |
| `nflasha5` (`/wbi`) | 42 293 120 | `9cb10112` |
| `nflasha7` (`/rootfs`) | 3 324 495 | `b969856d` |
| `nflasha15` (`/usr`) | 84 042 977 | `df198ecd` |
| `nflasha16` (`/android/system`) | 59 013 103 | `c77af80c` |

`nflasha17` (user data) and `nflasha2` (settings) are **not** in the update — user
data and settings survive a firmware update. Settings are handled separately:
`endupdate.sh` copies `backup/*/*/*.bin` from the update package into
`/setting/Backup.bin`, i.e. the region/language defaults are chosen **at flash time**.

Note that the images are *smaller* than the partitions they live in (e.g. 11.5 MB
image in a 30 MB partition). The rest of each partition reads as `0xFF` in a dump —
this is why naive dump maps show "empty gaps" that are in fact real partitions
(nflasha4, 6, 10, 11).

## Update mechanics (from `updater.img`)

`updater.img_unpacked/config/config.xml` drives the update as a list of steps:

| Step | Script | What it does |
|---|---|---|
| config | `us_crc32sum.sh` | CRC32 of config files |
| config | **`chkfirm.sh`** | **only** checks main-vs-sub LSI type via the power IC |
| config | `edit_mount.sh`, `keep_big_backup.sh` | append `mount1.conf`, preserve `psd.bin` |
| partconf | **`chknandcapa.elf`** | verify NAND capacity against `partinf.conf` |
| partconf | `us_mkfs.sh` | create filesystems |
| part_image | `us_crc32sum.sh` | CRC32 of the five partition images |
| darwin | `us_darwin_firm.sh` | **flash the power IC** |
| ca | `us_ca_firm.sh` | flash the CA chip |
| backup | `us_crc32sum_backup.sh` | CRC32 of `Backup.bin` |
| loader | **`loader_writer.sh`** → `pformat_normal/safe.elf` | **rewrite the bootloader**, MD5 manifest |

There is no version check that blocks a downgrade or a modified image.

## Inside the extracted firmware tree

```
config.yaml                     crypter CXD90014, model 0x41030035, version 3.21
firmware.fdat / firmware.tar    the payload (212 MB)
firmware.tar_unpacked/
  0100_config/                 mount.conf, big_backup.conf
  0110_backup/                 ← 11 complete Backup.bin files, one per region
  0300_partconf/partinf.conf   ← the partition table above
  0640_darwin/darwin_core.bin  power IC firmware (157 KB, Cortex-M3)
  0700_part_image/dev/         the five images + unpacked contents
  0800_appli/                  Android + lens files + settings defaults
updater.img_unpacked/          the updater OS: bin/, bodylib/, config/, usr/
```

`0700_part_image/dev/nflasha15_unpacked_unpacked/` is the camera's Linux root:

```
bin/  dfe/  kmod/  lib/  local/  sabin/  sbin/  scenario/  share/  tool/  wlan/
```

Two of those directories are covered in detail elsewhere: `dfe/` in
[05-dfe.md](05-dfe.md), `sabin/` + `scenario/` in
[06-av-dsp-scenario.md](06-av-dsp-scenario.md).
